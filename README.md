* **Live Deployment**: **[https://bear-bull-mu.vercel.app/](https://bear-bull-mu.vercel.app/)**
* **Repository**: `coder-manthan-007/Bear_Bull` *(Private)*

#### 🌟 Key Technical Highlights:
* **Discrete-Event Market Simulation**: Configurable financial laboratory with heterogeneous algorithmic trading agents (market makers, noise traders, momentum bots) and standalone C++ matching engine benchmarks.
* **100% ACID Append-Only Double-Entry Ledger**: Stored in PostgreSQL using 64-bit integer minor currency units (paise). Balance conservation invariant ($\sum \Delta \equiv \text{Balance}$) formally verified using property-based testing via `Hypothesis`.
* **Realistic Order X-Ray Diagnostics**: Explains fill mechanics against real market bid-ask snapshots, modeling real-world spread liquidity drag, queue priority, and slippage rather than naive mark-to-market fills.
* **Interactive 3D Book L2 & Primary IPO Center**: Immersive WebGL 3D order book depth visualization, SEBI-calibrated IPO lottery subscription engine with ASBA credit-blocking mechanics, and an integrated BearBull Copilot.

> <details>
> <summary><b>👨‍💻 Developer's Note on BearBull (Click to read)</b></summary>
> 
> * **The Core Problem**: The vast majority of retail "paper trading" platforms are fundamentally flawed: they execute orders instantaneously at the last traded price, completely ignoring order book depth, market impact, slippage, and bid-ask spread friction. This teaches traders unrealistic habits and fails to test automated execution logic.
> * **Architectural Solution**: BearBull was engineered to replicate real market microstructure. By feeding delayed NASDAQ and NSE feeds into an explainable fill engine, every execution produces an "Order X-Ray" showing why an order slipped, where it queued, and what liquidity fees applied. The core accounting engine adheres strictly to financial double-entry bookkeeping rules to guarantee zero balance leakages.
> * **Why It's Kept Private**: Contains proprietary C++ matching algorithms, discrete-event simulation kernels, and custom backtesting suites developed as part of ongoing financial systems research.
> </details>
